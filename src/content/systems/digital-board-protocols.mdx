<section id="layers">

<div className="section-heading"><span>01</span><h2>Separate electrical signaling, framing and application meaning</h2></div>

A communication link has several layers. Electrical signaling defines allowable voltages, currents and timing. Framing defines where a message or word begins and ends. Addressing and arbitration define which device may talk. An application assigns meaning to the payload. Confusing these layers produces circuits that look reasonable but fail to communicate.

UART describes asynchronous byte framing; the same frames can be carried at CMOS levels, through RS-232 drivers or on an RS-485 physical bus. SPI specifies a commonly used clocked peripheral interaction with device-specific framing. I²C specifies a shared open-drain bus with addressing and arbitration. Neither a successful byte transfer nor an ACK necessarily means the application performed the intended action.

Calculate payload rate after overhead. A 16-bit ADC result may require command, address, status or dummy bits; a register read may need a preliminary write of the register pointer. Include transaction gaps, conversion waits and retries. Then verify the MCU peripheral and software can sustain that timing without losing data.

</section>

<section id="uart">

<div className="section-heading"><span>02</span><h2>Follow an asynchronous frame and its timing error</h2></div>

In a common 8N1 UART frame, the line idles high, a falling start bit establishes timing, eight data bits are sent least-significant first, and one high stop bit ends the frame. N means no parity. The receiver samples around each bit center using its local clock, often with oversampling to detect and qualify the start edge.

<ProtocolTiming kind="uart"/>

The sender and receiver need compatible baud rate, word length, parity and stop-bit configuration. Optional parity detects selected error patterns but is not a full message checksum. A low stop sample produces a framing error; a sustained low level may indicate break. FIFO overrun means data arrived faster than it was serviced, even if the electrical frame was perfect.

Ten line bits carry eight payload bits in 8N1. At 115200 bit/s, maximum continuous payload is 11520 bytes/s before message overhead. Separate TX and RX support simultaneous traffic if both sides implement it. RTS/CTS can apply hardware flow control, but buffering and the time needed to stop an in-flight byte still matter.

<Equation tex={String.raw`R_{payload}=R_{line}\frac{8}{10},\qquad \Delta t_{drift}\simeq n\,\epsilon T_b`}/>
Here $\epsilon$ is relative baud mismatch and n is elapsed bit periods since start timing was established. At the stop-bit center of 8N1, n is roughly 9.5. A 2% mismatch creates about 0.19 bit of drift. Start-detection quantization, edge slew, noise and sampling algorithm consume additional margin; do not treat half a bit divided by frame length as a guaranteed tolerance. Crystal tolerance, RC-oscillator drift and integer baud-divisor error must all fit the budget.

CMOS UART pins are not RS-232 cable voltages. Use the required transceiver. On a cable, add return/common-mode and protection analysis. For a packet protocol, add length or delimiters, checksum/CRC, sequence handling and timeouts as appropriate. A parser must recover after a dropped or corrupted byte rather than remaining permanently shifted.

</section>

<section id="spi">

<div className="section-heading"><span>03</span><h2>Choose clock phase from launch and capture edges</h2></div>

A basic SPI connection has serial clock, controller-to-peripheral data, peripheral-to-controller data and a chip-select signal. The controller supplies the clock. A peripheral commonly shifts one bit out as another is shifted in, although read-only, write-only and half-duplex variants exist. The meaning of bytes, addresses and transactions comes from that device's datasheet.

CPOL selects clock idle level. CPHA selects whether capture uses the first or second clock edge after the idle state. With CPHA = 0, the first data bit must already be valid before the first capture edge. With CPHA = 1, the leading edge commonly launches the first bit and the trailing edge captures it. Confirm the device timing diagram because controller naming and peripheral requirements must align.

| Mode | Idle clock | Capture edge | Typical shift edge |
|---|---|---|---|
| 0 | Low | Rising | Falling |
| 1 | Low | Falling | Rising |
| 2 | High | Falling | Rising |
| 3 | High | Rising | Falling |

<ProtocolTiming kind="spi"/>

A read timing budget includes clock propagation to the peripheral, its clock-to-data-valid delay, data propagation back and controller setup time. For opposite-edge capture, a first bound is:

<Equation tex={String.raw`\frac{T_{SCK}}2\ge t_{clk,flight}+t_{CO}+t_{data,flight}+t_{setup}+t_{margin}`}/>
With 2 ns clock flight, 8 ns peripheral delay, 2 ns return flight and 3 ns setup, at least 15 ns half-period is needed before extra margin: about 33.3 MHz maximum in this simplified budget. A device's advertised 50 MHz SPI capability does not prove that a particular controller and route can read it at 50 MHz.

Chip select has setup and hold requirements too. Some parts frame every word with it; others keep it active over command/address/data. Some tri-state MISO only after a delay, so changing selects too quickly can cause contention. Multi-peripheral buses increase clock and data loading, and stubs create reflections. Series source termination can help point-to-point routes but must be assessed for the actual fan-out.

A 16-bit sample plus eight command/status bits at 1 MS/s needs at least 24 Mbit/s wire rate without gaps. DMA can reduce CPU service overhead but cannot violate peripheral timing. SPI generally provides no standard ACK, arbitration or mandatory integrity check; add device-supported CRC and application checks where data correctness requires them.

</section>

<section id="i2c">

<div className="section-heading"><span>04</span><h2>Follow bus ownership, addressing and acknowledgments</h2></div>

I²C uses SCL and SDA with open-drain behavior and pull-ups. Devices pull low or release; a low state wins if several devices act together. In the usual byte transfer, SDA changes while SCL is low and is sampled while SCL is high. A high-clock SDA falling transition marks START; a rising transition marks STOP. These deliberate exceptions frame the transaction.

For common 7-bit addressing, the first transferred byte contains address plus read/write bit, followed by an acknowledgment bit driven by the addressed receiver. Data bytes also have acknowledgment slots. A repeated START can change direction without releasing the bus. During a read, the controller normally acknowledges intermediate bytes and does not acknowledge the final byte before ending the transfer. The complete device sequence may require a register pointer write first.

<SystemsFlow labels={["START|own the bus", "Address + W|receiver ACK", "Register / data|byte + ACK", "STOP|release bus"]} caption="Example write transaction. A read may use a repeated START and a new address byte with the read direction."/>
Clock stretching lets a capable target hold SCL low until ready; the controller must support it and apply an appropriate timeout. Arbitration allows controllers to compare their released/driven SDA intent with the actual bus while SCL is high; a device intending high but observing low loses. Use the chosen controller's capabilities rather than assuming every I²C implementation supports every standard feature.

Address notation is a common software error: the 7-bit address and the transmitted 8-bit address/direction byte are different values. Some APIs expect the former, others ask for a shifted value. Reserved addresses, 10-bit addressing and device strap pins need explicit handling. An ACK indicates participation in that byte transfer, not proof of a completed internal write cycle.

</section>

<section id="pullups">

<div className="section-heading"><span>05</span><h2>Derive a valid pull-up interval</h2></div>

The released line charges through pull-up R into total bus capacitance C. A first-order rise from 30% to 70% takes $0.8473RC$. A smaller resistor speeds the edge but raises low-state sink current. The minimum value must respect the device's guaranteed low voltage at its allowed sink current.

<Equation tex={String.raw`R_{max}=\frac{t_{r,max}}{0.8473C_{bus}},\qquad R_{min}=\frac{V_{DD}-V_{OL,max}}{I_{OL}}`}/>
For a teaching 400 kbit/s design using a 300 ns rise-time limit, 3.3 V rail, 100 pF bus, 0.4 V low allowance and 3 mA sink capability, the interval is approximately 967 Ω to 3.54 kΩ. A 2.2 kΩ choice gives about 186 ns rise and 1.32 mA sink at 0.4 V. Check every connected device, resistor tolerance and actual capacitance.

At 400 pF with those same assumptions, maximum resistance falls to about 885 Ω, below the 967 Ω current-limit minimum. There is no valid passive resistor interval. Reduce capacitance, slow the bus with appropriate timing limits, or use a suitable buffer/active pull-up architecture. Putting several modules' pull-ups in parallel can accidentally violate sink-current limits even when each module works alone.

Buffers can change capacitance partitions, low levels, rise behavior and arbitration/stretching compatibility. A generic bidirectional voltage translator can fail with some bus-buffer offsets or operating states. Long cables require noise, delay and ground-offset analysis; a board-level open-drain bus should not be extended indefinitely just because it has two wires.

A target stuck holding SDA low can block all devices. Some systems attempt a documented clock-pulse bus-clear procedure and STOP; others need a device reset or power cycle. Apply the controller and target's specified recovery rules and timeout. Pull-ups alone cannot recover a latched state machine.

</section>

<section id="audio">

<div className="section-heading"><span>07</span><h2>Clock continuous audio and widen memory transfers</h2></div>

I²S carries a continuous digital-audio stream using bit clock, word select and serial data. Standard stereo word select identifies left and right channels, and changes one bit-clock period before the next word's most significant bit. This alignment differs from left-justified audio and from SPI framing. Both endpoints must agree on format, sample width, slot width, clock role and capture timing.

<Equation tex={String.raw`f_{BCLK}=2W_{slot}f_{sample}`}/>

For 48 kS/s stereo in 32-bit slots, bit clock is 3.072 MHz even if each useful sample contains only 24 bits. At 96 kS/s it is 6.144 MHz. A converter that separately requires a 256-times-sample-rate master clock needs 12.288 MHz at 48 kS/s; that ratio is a device requirement, not a universal I²S rule. A system must establish who generates each clock and how the analog converter derives its sampling time.

A clock used by an ADC or DAC can carry phase noise into the conversion even when digital words decode correctly. Two independently generated audio sample clocks also drift relative to each other. Buffering alone cannot absorb an unbounded rate difference; use a common clock, controlled rate adaptation or an appropriate asynchronous sample-rate converter. Configure DMA and word packing so signed samples are not shifted by one bit or placed in the wrong channel slot.

Quad and octal SPI-style memory interfaces transfer several data bits per clock; DDR variants may use both edges and a data strobe. Commands, lane direction and dummy cycles are device-specific. They increase bandwidth but introduce multi-bit skew and source-synchronous timing requirements. A four-lane interface at 50 MHz has a 200 Mbit/s raw single-edge data phase, not 200 Mbit/s guaranteed payload across commands and gaps.

Primary audio reference: [NXP UM11732, I²S Bus Specification](https://www.nxp.com/docs/en/user-manual/UM11732.pdf). Use the memory device's own timing and command documentation for widened serial interfaces.

</section>

<section id="choose">

<div className="section-heading"><span>06</span><h2>Compare useful work and failure behavior</h2></div>

For an I²C register write carrying address, register index and one data byte, three nine-clock byte slots use 27 clocks, excluding START/STOP setup and any stretching. At 400 kbit/s this is at least 67.5 μs, so small transactions deliver far less than 400 kbit/s of useful register data. Burst transfers amortize address overhead; they also require the device's auto-increment and boundary behavior to match the plan.

UART suits asynchronous point-to-point byte streams and often cable transceivers. SPI offers simple high-throughput board links with explicit selection and carefully budgeted edges. I²C can share addressed low-pin-count peripherals when pull-ups, capacitance and recovery are managed. Choose using direction, device support, route length, rate, latency, voltage domains and fault containment rather than a nominal bit-rate comparison alone.

Primary references: [NXP UM10204, I²C-bus Specification and User Manual](https://www.nxp.com/docs/en/user-guide/UM10204.pdf), [TI, I²C Bus Pull-Up Resistor Calculation](https://www.ti.com/lit/an/slva689/slva689.pdf), and [TI UART training](https://www.ti.com/lit/ml/swrp216/swrp216.pdf). Device-specific SPI framing and limits belong to the selected peripheral's timing diagram.
